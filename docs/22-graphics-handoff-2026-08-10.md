## Status: not fixed

## Architecture answer

Sunpad and Ballpad share the high-level CPU technique, not the complete runtime:

- Both use DolRecomp to ahead-of-time translate GameCube PowerPC code.
- Neither executes its matching decompilation project; those repositories are
  symbol and behavior references.
- Sunpad loads generated code into ModernGekko, using Dolphin-derived hardware,
  scheduling, vertex loading, and the Dolphin Metal renderer.
- Ballpad directly links StrikersRecomp-generated code to its own HLE host,
  GXRuntime retail FIFO frontend, gxcore plan builder, and Aurora/Dawn-to-Metal
  renderer.

Therefore Sunpad validates DolRecomp plus a mature Dolphin-derived runtime. It
does not validate Ballpad's custom GX state reconstruction, QuickBoot restore,
skinning path, EFB readback, or frame ownership.

## What the frame review established

### Confirmed

1. A 28-second QuickBoot recording showed the stadium and field rendering
   consistently while skinned players remained flattened/head-heavy across
   every sampled frame. This was not a one-frame tackle or fall animation.
2. A true fresh guest boot reached the same stadium with much less catastrophic
   character deformation. Multiple players were upright and animated for more
   than ten minutes. This proves that restore state materially changes the
   result, but it does **not** prove the fresh renderer is accurate.
3. The old `QuickBoot.bss` was still a v3 file captured at 13:49. It had not
   been regenerated by the fresh A/B run.
4. The old v3 file is now recoverably quarantined as
   `Documents/QuickBoot.incompatible-v3.bss`. A second preserved copy is
   `Documents/QuickBoot.pre-fresh-ab.bss`.
5. `host/src/ballpad_ios_host.cpp` opened a second Aurora recording frame after
   `dol_aurora_initialize` had already opened one. That duplicate open was
   removed. It was a real lifecycle bug, but removing it did not eliminate the
   visible character problem.
6. LLDB caught `aurora::gfx::push_verts` dereferencing a null
   `g_recordingFrame` (`0xc8`) on the guest thread. The stack ran through
   `submit_draw_plan` -> `core_plan_observer` -> frontend display-list decode.
   Treat this as evidence of invalid frame ownership, not yet as a complete
   explanation for all geometry errors.
7. Earlier QuickBoot work restored missing CP indexed-array base/stride
   bindings and rejected invalid indexed spans. Current live counters showed no
   ongoing vertex-decode failures, so the remaining issue cannot be dismissed
   as the original RAM[0]/stride-zero bug.
8. gxcore currently uses the per-vertex PN selector for positions but a
   draw-wide normal matrix for lighting. Dolphin/Aurora reference code uses the
   per-vertex selector for both position and normal palettes. This guarantees
   incorrect skinned lighting; by itself it should not move clip-space
   positions, so it is not a sufficient geometry diagnosis.

### Not established

- There is no pixel-accurate or silhouette comparison against Dolphin running
  the same Strikers scene.
- The latest fresh-path image is not an accepted correctness baseline.
- A new v4 QuickBoot image has not been captured and round-tripped.
- Post-match/replay transitions remain unreliable on QuickBoot-restored state.
- Physical iPhone/iPad rendering and performance have not been validated.

## Next session: highest-value experiments

Do these in order. Do not resume by tweaking matrix math blindly.

1. **Create an authoritative oracle.** Run the same `G4QE01` scene in current
   Dolphin with the same teams/stadium and capture several standing/running
   frames. Compare silhouettes, joints, shadows, lighting, projection, and
   camera crop against Ballpad.
2. **Capture one problematic skinned draw end-to-end.** On a fresh boot, log
   display-list bytes, VCD/VAT, CP array bindings, PN selectors, position and
   normal palettes, decoded positions, final clip-space bounds, topology, and
   draw sequence for one player mesh across consecutive frames.
3. **Compare against Dolphin's vertex-loader semantics.** In particular verify
   whether PN bytes are raw matrix-row indices or palette indices at every
   boundary and whether the normal palette uses the same per-vertex selector.
4. **Replay the captured draw offline.** Use the gxcore replay tool so live
   guest scheduling, EFB readback, and SwiftUI composition are removed from the
   experiment. If the replay is wrong, fix frontend/gxcore/shader semantics. If
   replay is right but live is wrong, return to frame ownership/state lifetime.
5. **Only after fresh-path parity, regenerate v4 QuickBoot.** Capture at the
   documented idle side-choice/stadium-card boundary, restore it, and compare
   five frames plus the complete post-match transition against fresh boot.
6. **Re-run controls on both form factors.** Reset layout defaults, then compare
   phone and iPad safe-area placement against Sunpad. Specifically inspect A/X/Y
   separation, C-stick clearance, shoulder edges, and three-dot hit testing.

## Do not repeat these mistakes

  QuickBoot frame.

  correct.

- Do not explain persistent multi-frame deformation as tackle animation without
  a neutral-input sequence proving recovery.

  canvases and resetting persisted defaults.
