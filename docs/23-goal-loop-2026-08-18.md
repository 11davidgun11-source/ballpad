# Ballpad goal loop — 2026-08-18

## Goal

Turn Ballpad into a stable, playable iPhone and iPad app with the practical
control layout, discoverability, and performance bar of the local Sunpad
reference. Do not call a build, a boot screen, or a single screenshot proof of
release readiness. The product is ready for a wider test only when the defined
end-to-end gates pass on both form factors and a physical-device pass exists.

## Evidence-based baseline

The project is not a blank or unplayable shell. This checkout contains a
universal arm64 iOS/iPadOS 17 target, generated Strikers inputs, the native
host and renderer archives, import/onboarding, a Sunpad-derived touch overlay,
controller support, and UI tests. On 2026-08-18 the rebuilt iPhone 17e
Simulator app reached a live match under real touch navigation on iPhone 17e,
and the default renderer displays fresh game output on both iPhone 17e and
iPad (A16). Measured guest throughput was roughly 19–70 million
blocks/second; a current phone in-match capture showed 23 fps, while historical
segments varied higher by device and scene.
The simulator's raw screenshot API can place an upright landscape app inside
a portrait framebuffer. Inspect the game content before using the explicit
rotation option in `scripts/upright_proof.sh`; do not rotate merely because
the PNG dimensions are portrait.

This does **not** establish release quality. A fresh-boot white EFB was traced
to the experimental GXCore cutover; the product default is now the proven live
Aurora GX path, while GXCore requires `DOL_GX_CORE=1`. Renderer parity for
QuickBoot restore and post-match visual parity is still unaccepted; physical
iPhone/iPad performance and lifecycle behavior remain unproven. A 2026-08-18
v4 QuickBoot restore reached a match, advanced frames, and restored its audio
DMA state into an active iPad Simulator playback queue, but is still not a
visual-parity or physical-audio proof. The same run confirmed that hiding SDL's
auxiliary window without
re-parenting its controller leaves EFB presentation working; UIKit's existing
SDL appearance-transition warnings occur during SDL startup and remain an open
diagnostic, rather than being attributed to that re-parenting path.

The remaining render gate is now a parity and endurance gate (including a

The iPad touch-only XCUITest was also repaired to use the host's exact

## Operating loop

Repeat this loop for one narrow hypothesis at a time. Preserve unrelated user
changes and do not change the test game or generated assets.

1. **State a measurable hypothesis.** Name the affected scene and expected
   outcome, for example: “the fresh-match EFB readback advances and remains
   nonblank for 60 seconds after touch-only entry.”
2. **Build exactly the affected layers.** Build `BallpadHost` after host
   changes, then build the Xcode target for one selected Simulator. Use
   `scripts/sim_mutex.sh`; one simulator at a time prevents GPU/window
   cross-contamination.
3. **Run from a known state.** Record whether this is fresh boot or QuickBoot,
   renderer scale, device profile, and test input. Capture both boot/interstitial
   and match evidence; a blank transitional frame is not a renderer verdict.
4. **Collect bounded diagnostics.** Keep normal logs quiet. Use the Share
   Diagnostic Log snapshot for host running/paused state, guest step budget and
   time, Aurora present count, EFB frame version/size, and boot source. Enable
   deeper environment-gated instrumentation only for a specific experiment.
5. **Compare against an oracle.** For rendering, capture the same scene in
   Dolphin and compare camera crop, player silhouettes/joints, lighting,
   shadows, HUD, and frame progression. Sunpad is the controls/layout reference,
   not proof that Ballpad's GX path is correct.
6. **Implement the smallest causal repair.** Do not tune matrix/shader math
   from a screenshot alone. Prefer a captured draw/replay or an explicit
   lifecycle/readback invariant.
7. **Verify and record.** Re-run the narrow gate, then its adjacent regression
   gate. Add the evidence, command, device, and remaining uncertainty to the
   validation ledger. Update product documentation only with claims the new
   evidence supports.

## Priority gates

| Priority | Gate | Required proof |
|---|---|---|
| P0 | Fresh render correctness | Dolphin comparison for a static and moving match scene; no persistent mesh deformation, wrong crop, blank, or frozen EFB. |
| P0 | Playable touch loop | PASS on iPhone and iPad Simulator: fresh boot, real-overlay menu-to-match, then 60 seconds of stick + face/shoulder input while the guest advances. Physical-device equivalent remains open. |
| P0 | Lifecycle safety | PASS on iPhone and iPad Simulator: background/foreground resumes, and the in-app Touch Control Settings sheet demonstrably freezes then resumes the guest. Physical-device lifecycle remains open. |
| P1 | QuickBoot/post-match | New v5 semantic rebind improves restore from 4/6/22 to 7 loaded textures/16 arrays/22 copy caches, but players remain malformed; determine remaining scalar GX/copy-cache state and prove visual parity before enabling it. Default remains fresh boot. |
| P1 | Controls parity | Reset defaults and visually compare Sunpad placement/hit areas on actual phone and iPad safe-area canvases; test controller handoff on physical hardware. The Simulator-only mapping/overlay proof hook is a regression aid, not a substitute. |
| P1 | Performance | Same-scene 60-second samples, with frame/present rate and guest step cost, then physical-device Instruments captures. |
| P2 | Release hygiene | Clean-clone dependency/bootstrap story, licenses/notices, tested archive, and README claims aligned to evidence. |

## Current commands

```sh
cmake --build work/strikers/build-ios-sim --target BallpadHost gxruntime_aurora -j8
libtool -static -o work/strikers/build-ios-sim/merged/libBallpadEngine.a \
  $(head -n 119 work/strikers/build-ios-sim/merged/libs2.list)

xcodebuild -project app/Ballpad.xcodeproj -scheme Ballpad \
  -configuration Debug -destination "id=$BALLPAD_PHONE_UDID" \
  -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build

SIMCTL_CHILD_BALLPAD_AUTOSTART=1 \
SIMCTL_CHILD_BALLPAD_PERF_LOG=1 \
SIMCTL_CHILD_BALLPAD_LOG_FILE='$HOME/Documents/ballpad.log' \
xcrun simctl launch "$BALLPAD_PHONE_UDID" com.ballpad.strikers
```

Normal builds take the correctness-first fresh path. For a QuickBoot diagnostic,
add `SIMCTL_CHILD_BALLPAD_ENABLE_QUICKBOOT=1`; add
`SIMCTL_CHILD_BALLPAD_NO_QUICKBOOT=1` to force fresh boot even then. Never call
a QuickBoot restore healthy until it has passed the dedicated visual-parity gate.
For a fresh autostart diagnostic that must preserve the existing snapshot, add
`SIMCTL_CHILD_BALLPAD_SKIP_QUICKBOOT_SAVE=1` as well.

## Exit criteria for this goal

The goal is complete only when P0 and P1 gates have current evidence on phone
and iPad, physical-device smoke/performance results are recorded, diagnostics
can distinguish host/render/lifecycle failure without user data leakage, and
the root README accurately labels any remaining limitations. Until then,
Ballpad remains development software rather than a release-quality emulator.
